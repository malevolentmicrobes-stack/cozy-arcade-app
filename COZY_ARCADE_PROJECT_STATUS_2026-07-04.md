## HUD fixes shipped today (sw v101 → v103)

**Duplicate/offscreen HUD home buttons (v101→v102, commit `fd85901`):** Two legacy functions, `addHudHome()` and `standardHud()`, each independently created their own untagged home button in the Solo/Domain HUD, uncoordinated with the canonical `ensureHudButton`/`renderHudControls` system. A slow (4s-interval) dedupe sweep cleaned them up eventually, but a real window existed right after starting a game where a duplicate button sat offscreen (`x:-5`). PHASE2 (reference copy at the time) had already deleted both button-creation blocks; ported that exact deletion — net negative lines, no new wrapper. Also found and fixed a second bug this exposed: with the legacy creators gone, the canonical home button was left invisible (a CSS rule hiding `[data-home]` buttons, written back when the legacy button provided the visible affordance, was never removed). Live-validated at 390×844: exactly 4 buttons, all on-screen, home button clickable, FSRS 17/17, smoke 6/6.

**Double-rendered Pause/Exit icons (v102→v103):** User supplied screenshots (`/Users/rebekahbetar/Documents/glitch source/HUD GLITCH/`) taken live, after the above fix was already deployed, showing the Home icon still appearing 0/1/2 times across rapid screenshots, plus older (2026-06-25) DevTools screenshots showing doubled `::before`/`::after` pseudo-element content on the Pause button. Live-instrumented computed styles (Playwright, real Upload flow, mobile + desktop viewports) found: `#soloPause` and the Exit/`[data-home]` button each had TWO separate icon-painting mechanisms active simultaneously — an old, hardcoded `::after{content:'Ⅱ'}` / `::after{content:'×'}` rule (from before the current icon system existed) stacking on top of the newer, unconditional `.hudIconButton371::before{content:attr(data-hud-icon)}` rule. Undo and Settings buttons (which never carried the old legacy classes) rendered clean with only one pseudo-element — direct proof the newer system alone is sufficient. Removed only the two old `::after{content:...}` declarations, left the accompanying `font-size:0` text-hiding rules untouched (they're not the cause, and are unconditional — verified they still correctly hide real text at both mobile and desktop viewports before and after the change). Live-validated: `::after` computed content is `none` on every HUD button now, single clean icon render, screenshot-confirmed, home-button click still works, FSRS 17/17, smoke 6/6, zero page errors.

## Aesthetic/UX goal, for context on all HUD work
Per prior sessions' `GOAL CLARIFIED` note: this app is meant to work smoothly for OTHER users, not just as a personal study tool — glitches like flickering/doubled icons are exactly the kind of thing that erodes trust in an unfamiliar app faster than a missing feature would. HUD work should aim for: one visible control per role, no visual doubling/ghosting, consistent icon rendering across breakpoints. Full reveal-panel consolidation (the bigger, still-open architectural item) is a separate, larger effort — see PHASE2's RECTIFIER_PLAN 2026-07-04 addendum for that plan; not part of today's PHASE1-only HUD work.
